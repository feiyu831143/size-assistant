# 评论偏码分析

目标：把"很多人说偏小"这类噪声，转成"你这个身材该 +1 码"的可执行结论。

## 采集字段

逐条从评论中提取，缺任一字段的评论**不计入统计**（只做定性参考）：

| 字段 | 说明 |
|---|---|
| 身体数据 | 身高+体重，或实测胸围/腰围/脚长；只有"我 130 斤"也算可用（配合身高） |
| 实穿码 | 用户购买的码 |
| 结论 | 偏大 / 合适 / 偏小（三分类；"质量很好""物流快"不入库） |
| 不合适的具体部位 | 胸 / 肩 / 腰 / 臀 / 大腿 / 衣长 / 袖长 / 整体 |
| 洗后变化 | 是否提到缩水、变松 |
| 穿着方式 | 内搭厚度、袜子厚度（鞋类） |

## 判定门槛

| 条件 | 结论 |
|---|---|
| 同向占比 ≥ 60% **且** 有效样本 ≥ 10 | 可给 ±1 码偏移建议 |
| 同向占比 40-60%，或有效样本 5-9 | 不分整体偏移，改为**按体型分段**给建议（如"78 kg 以上偏小，75 kg 以下正常"） |
| 有效样本 < 5 | 不给偏码结论，回到尺码表本身，并说明评论样本不足 |
| 偏移集中在单一部位 | 不给换码建议，给选款建议（如"袖长普遍不足 → 选袖长可改或长款"） |

分段方法：把有效评论按身体数据排序，看"偏小"结论是否聚集在尺码表临界值一侧。若临界两侧结论相反，说明尺码表本身正确，只是用户的日常码习惯与本品不符。

## 必须排除的偏差

1. **临界人群聚集**：买 borderline 码的人最容易留言，且倾向说"偏小、建议拍大一码"。这是幸存者偏差的主要来源，会让整体结论系统性偏向"大一码"。修正：只在同身体数据段内比较，不做全量比例。
2. **退货者不留言**：留言者多为收货保留的人，未留下的人没有声音，分布右偏（偏大方向的抱怨被低估）。
3. **部位归因错误**：评论说"偏小"常指袖长或衣长不够，而尺码表争议项是胸围。不加区分会把衣长问题误判为胸围版型问题。
4. **洗后误判**：穿了两次变紧被写成"版型偏小"。区分首穿与洗后，洗后信号交给 `shrink`。
5. **女性胸围归因**："胸围紧"多来自罩杯而非背围。需区分下胸围与上胸围，否则会给大罩杯用户推荐过大的 band。
6. **模板好评**：卖家邀评/追评里的"按平时码数拍就行""尺码标准"是话术，不构成数据。剔除同时给不出身体数据的条目。
7. **身材描述口语化**：130 斤 = 65 kg（不是 130 kg）；"1 米 62" = 162 cm。用 `unit` 子命令换算，不要心算。
8. **不同码段混算**：S 码偏大与 XL 码偏小可能同时成立（放码规则不一致），不要合并成"整体偏大"。

## 与尺码表冲突时的优先级

```
商品页成衣实测数据
  > 含身体数据的结构化评论
  > 无身体数据的评论倾向
  > 客服话术 / 模特参考 / 用户自我描述"我平时穿 L"
```

出现冲突时不要择一，而是明确说明冲突及两种解释：

- 解释 A：**批次/工厂差异**——评论来自早期批次，与当前库存版型不同。
- 解释 B：**口径误读**——评论者把净体表当成衣表，或把衣长不足归为胸围不足。
- 解释 C：**尺码表错误**——商家表填错（可校验：各码胸围是否等差递增 4-6 cm，跳档或倒挂即为错表）。

给出双码建议 + 判据：若退换成本低（运费险），按评论倾向选；若退换麻烦，按成衣表选并挑松量更宽的一档。

## 校验尺码表是否填错

快速检查：相邻码同一部位差值应在 4-6 cm（胸围）、2-4 cm（腰围）、1-2 cm（衣长）。出现等差不等（M→L 突然 +10）、单位混排（一行 cm 一行 inch）或数值倒挂，判为错表，此时应转向以评论 + 品牌通用表为准，并明确告知用户商品表不可信。
